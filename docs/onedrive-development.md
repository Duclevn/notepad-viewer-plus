## Set up another Windows computer

1. Sign in to the same OneDrive account and enable syncing of `Apps/notepad-viewer-plus`. The OneDrive root/Windows username may differ.
2. In Explorer, choose **Always keep on this device** for the complete project. Wait for OneDrive to finish downloading before opening Git or building. Confirm hidden `.git` directories and `third_party` SDK files are present.
3. Install Git for Windows, Node.js 22.x, version 22.12 or later (tested here with 22.23.2; other Node versions must satisfy both Vite and Vitest engine requirements in `renderer/package-lock.json`), CMake 3.25+, and Visual Studio **2022** Build Tools with **Desktop development with C++**, MSVC x64/x86 tools, and a Windows SDK. The Notepad++ and WebView2 SDKs are already included under `third_party`; they do not need machine-specific paths.
4. Open PowerShell in the downloaded checkout and run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Build-Development.ps1 -InstallDependencies
```

`npm ci` installs the exact lockfile dependencies for that computer. This requires registry access. The helper checks renderer version metadata, TypeScript, unit/security tests, the production build, and strict package size; then configures fresh x64/x86 native builds and runs native tests. Any failed command stops the helper. It resolves project paths from the script rather than a fixed username or the caller's working directory.

For subsequent builds:

```powershell
.\Build-Development.ps1
.\Build-Development.ps1 -Architecture x64
.\Build-Development.ps1 -Package
```

Native builds are stored in `%LOCALAPPDATA%\NotepadViewerPlus\development\<checkout-path-hash>\x64` and `\x86`. Optional validated packages are written to each native build's `packages` directory, **not** over the existing root ZIPs. The helper prints the exact paths. CPack staging stays machine-local. Use these locations rather than the older in-checkout build commands when working directly in OneDrive.

To install a newly built package, close Notepad++ and pass that package's printed absolute path to the current root installer using `-ZipPath`. Do not assume the root ZIP has been updated by a local build. Notepad++, the Microsoft Edge WebView2 Evergreen Runtime, and the supported Microsoft Visual C++ v14 Redistributable matching the plugin architecture must be installed separately on each computer. Pass the intended installation's `-NotepadRoot` explicitly; the installer does not validate host architecture. See [New computer setup](../NEW-COMPUTER-SETUP.md) for the complete running/development checklist. Merely syncing the project does not install the plugin.

## Synchronization safety

- Work on **one computer at a time**. Close editors/build tools, finish Git operations, and wait for OneDrive to report **Up to date** before switching computers. OneDrive is file synchronization, not transactional Git replication; concurrent changes can corrupt Git metadata or create conflicts.
- `.gitignore` does **not** exclude files from OneDrive. This checkout preserves `renderer/node_modules` and generated `renderer/dist`; they are synced and can create substantial sync traffic. Reinstall dependencies on the second computer rather than trusting binaries produced on another system. Never run `npm ci` concurrently on two synced computers.
- Do not place native caches back in the synced checkout. Absolute source/compiler paths and generated Visual Studio files are not portable between computers.
- If OneDrive conflicts appear, stop work on both computers and preserve both versions before resolving them. A separate non-synced clone with a real Git remote is safer for concurrent development.
- Cloud upload completion, second-computer setup, and the Notepad++/WebView2 manual UI smoke matrix require checks on those systems. Successful local builds/tests cannot guarantee them.

## Pre-existing package-validator caution

The independent review identified a pre-existing safety issue in `packaging/plugin-admin/validate-package.ps1`: a manually supplied `-ReportPath` can overwrite/delete an existing file, including the input ZIP if the paths collide. Use the default report path (`<ZIP>.validation.json`) and never point `-ReportPath` at a package or another valuable file. The new build helper uses only the safe default. No retained ZIP was changed. This migration does not modify the validator's custom-output behavior.

The SDK directory `third_party/npp-plugin-template` currently has its own complete `.git` repository, while the outer repository records it as a gitlink without `.gitmodules`. This predates the move. OneDrive relocation preserves it, but `git submodule update` is not a supported bootstrap for this checkout. Do not replace it with an empty directory or use a fresh clone as a substitute without first fixing SDK provisioning.
